Brief

Inquiries pairs two members for a single one-to-one conversation around one contemplative question. A member raises their hand, tells us which languages they can hold a deep conversation in, and the system does the rest — matching them, dealing a question, and pointing both people at WhatsApp to arrange the call. No in-app chat to build. No scheduling engine. The product carries the intention; the conversation happens where conversations already happen.

This is the heart of the platform — the thing the name inquiry has been waiting for. Everything here is deliberately small: one form, one list, one card with a question on it.

step · 1
Raise your hand

Mark yourself available. Choose a preferred language, plus any others you'd be comfortable in.

step · 2
Get matched

Every Monday the system pairs available members who share a language, and deals each pair one question.

step · 3
Arrange it yourselves

WhatsApp, Signal, Telegram — whatever you both shared. We draft the first message; you find the hour.

step · 4
Hold the inquiry

45–60 minutes. One asks, the other speaks; swap halfway. Then mark it complete and return to the pool.

Becoming
available.

One screen, no wizard. The whole ask is four decisions: am I in, what language do I prefer, what else could I manage, and how should my match reach me. Contact details are collected here — up front — so that match day needs zero setup from either side.

Decisions

Preferred language is required, additional languages optional. The matcher treats them differently — see the machine, below. Cadence is personal (weekly / bi-weekly / monthly), so enthusiasm never becomes obligation.

Privacy

The number is never public and never shown on a profile. It is revealed only to a confirmed match, only after the round runs. The form says exactly that, in small type, where the number is typed.

Open question

Should availability auto-pause after two rounds where the member never arranged the call? Protects future partners from silence.

PAGE 02 /inquiries

Your
inquiries.

Not an inbox — a shelf. The active match is a single hero card where the question is set in serif quotation, larger than the partner's name. History collapses into quiet rows: the question you held, the person you held it with, a date. One state pill does the narration: NEW → ARRANGED → COMPLETED (or SKIPPED).

Decisions

One active match at a time — by design. The empty state is not an error: “You're in the pool. Next round Monday.” The shared language is shown as a chip so members instantly know which language the call will be in.

Empty state

Members who are available but unmatched see the next round date and a single line of reassurance — never a spinner, never a blank screen.

The
inquiry.

Everything needed to get from “you've been matched” to a real call, on one screen. The question is dealt face-up in a dark card — the only dark surface in the app, reserved for this moment. Below it, four numbered steps. Beside it, the person and one loud green button.

Decisions

The WhatsApp button deep-links with a pre-filled first message (wa.me/<number>?text=…) so the awkward opener is already written. “Copy message” covers Signal / Telegram, where prefill isn't reliable.

Escape hatch

“Skip this round” releases both members back to the pool without blame, and tells the partner gently. Silence is the only failure mode worth designing against.

Open question

Allow one re-draw of the topic per match, if both tap “draw another”? Keeps agency without making the deck a menu.

Behind the curtain

The machine,
briefly.

The matcher is a Monday-morning batch job, not a realtime system. It only needs to be fair, language-safe, and unsurprising. Members never see any of this — they see one card appear.

# schema sketch — inquiry-api
type InquiryAvailability {
  available: Boolean!
  preferredLanguage: LanguageCode!
  additionalLanguages: [LanguageCode!]!
  contactMethod: ContactMethod! # WHATSAPP …
  contactHandle: String!
  cadence: Cadence!
}
 
type Inquiry {
  id: ID!
  partner: Member!
  topic: InquiryTopic!
  matchedLanguage: LanguageCode!
  status: InquiryStatus! # MATCHED|ARRANGED|COMPLETED|SKIPPED
  round: Date!
}
Language

A shared language is required, never optional. Pairs are scored: preferred ∩ preferred is the best match; preferred ∩ additional is acceptable; additional ∩ additional only when the pool is thin. The matched language is stored and shown on the card.

Repeats

No re-pairing of the same two members within six months.

Ties

Among equally valid pairings, closer time-zones win — afternoon meets evening, not 3 a.m.

Cadence

Personal, not global: weekly, bi-weekly, or monthly. A member is only in the Monday pool when their own clock says so.

Topic

One question per match, dealt from a curated deck of 52. Both members see the same card. Neither chose it — that's the point.

Unmatched

An odd member out stays in the pool with priority for the next round, and is told so plainly.

Next

Small surface, deep feature.

Three screens, one batch job, zero realtime infrastructure. The order of work: validate the copy on this page with a handful of members, land the schema in inquiry-api, then build the sign-up screen behind the inquiries remote-config flag. The matcher can run by hand for the first few rounds — the design doesn't know the difference.
